Escalation rule: escalated = (tier = 'enterprise' AND priority = 'urgent'); every other combination is false. Pro and free tickets are always escalated = false, whatever the priority or the customer's wording.
Priority measures service impact, not tone: urgent only for production down or data loss. A subject saying "URGENT" does not make priority urgent; a plain refund request is normal priority; a "how/where do I" question is low; one user unable to log in is high, whatever the tier.
Refund requests have charge_date set: each one gets its own policy lookup with as_of = that ticket's created_at date (YYYY-MM-DD, never charge_date), then approve / deny / credit under the returned policy_in_force, stored in policy_version. Everything else gets refund_decision = 'n/a' and policy_version NULL.
