Plexus
Watch Presentation Run it GitHub

One Postgres runs the agent, its knowledge, its memory, and the loop that makes it better.

Plexus is a working demo. A support-triage agent runs inside the database with one SQL call. It looks up the refund policy that was in effect on each ticket's date, an agent on the refunds table vetoes a bad refund before it commits, every decision cites its evidence, and a tuner rewrites the agent's own harness from its past runs.

Every run in these videos is real: the agent, the veto and the policy change ran against the database while recording. Waits on the model are sped up.

What is in the one database

pg_synapse
The agent runtime. SELECT synapse.execute(...) runs the whole tool loop, and inline triggers put an agent in front of a write.
pg-raggraph
Retrieval with effective dates: ask for the policy as of a day and get the version that applied then.
stele
Memory with evidence. Each belief cites an artifact, a correction supersedes it, and you can ask what was believed at any instant.
chunkshop
Ingest: the policy corpus and the agent's own past runs, as vector tables next to everything else.
harness2 (the idea)
Hold the model fixed and tune everything around it from evidence. Reimplemented inside pg_synapse; no harness2 code is used.

What it does not do yet, said plainly in the deck: a small model passes the triage task only some of the time, the veto is a model call per insert (seconds, not milliseconds), long runs sometimes stop early, and any dollar figure is an assumption until measured.

Run it

You need Docker, psql, git, uv, Python 3.12 and Ollama. The first make up builds Postgres with pg_synapse, which takes a few minutes.

ollama pull qwen3:4b-instruct-2507-q4_K_M
OLLAMA_HOST=0.0.0.0:11434 OLLAMA_CONTEXT_LENGTH=32768 ollama serve &

git clone https://github.com/TheYonk/plexus && cd plexus
make deps venv up ingest seed   # siblings at pinned commits, then the stack
make run                        # the agent triages 8 tickets
make veto                       # a bad refund is rejected inside the transaction
make ui                         # http://127.0.0.1:8766/ and /deck

The default 4B model is small enough for a laptop and fails the full triage check more often than not. Point the agent at a bigger OpenAI-compatible model with make seed LLM_MODEL=... LLM_BASE_URL=...; the videos used Qwen3.6-35B-A3B on vLLM. The README has the rest: memory, tuning, the videos.
